🖥️ สไลด์หน้า 2: ที่มาและความสำคัญ & Research Question
คลิกเปลี่ยนสไลด์ — เน้นย้ำประเด็นคำถามวิจัยหลัก
"ในปัจจุบัน ข้อมูลรีวิวบนโลกออนไลน์มีปริมาณมหาศาลครับ การทำ Sentiment Analysis จึงเป็นงานหลักของ Pattern Recognition ในการสกัดอารมณ์บวกหรือลบออกมา

ในอดีต LSTM เคยเป็นมาตรฐานทองคำของงานประมวลผลภาษาธรรมชาติ แต่ต่อมาเกิดการเปลี่ยนกระบวนทัศน์ (Paradigm Shift) ครั้งใหญ่ด้วย Transformer และ BERT

คำถามวิจัย (Research Question) สำคัญของโครงงานนี้คือ: 'เมื่อนำ LSTM และ BERT ที่ผ่านการ Fine-tune มาแก้โจทย์เดียวกัน ภายใต้สภาพแวดล้อมที่มีการควบคุมอย่างเข้มงวด — โมเดลใดจะให้ความแม่นยำสูงกว่ากัน และที่สำคัญที่สุดคือ เราต้องแลกมาด้วยต้นทุนการประมวลผล (Computational Cost) เพิ่มขึ้นกี่เท่า?'"
🖥️ สไลด์หน้า 3: สถาปัตยกรรม LSTM (Recurrent Baseline)
คลิกเปลี่ยนสไลด์ — ชี้แผนภาพลำดับการไหลของข้อมูลจากซ้ายไปขวา
"เริ่มที่โมเดลพื้นฐานคือ LSTM ครับ กลไกหลักของ LSTM ทำงานแบบ ตามลำดับเวลา (Sequential Recurrence) อ่านคำทีละคำจากซ้ายไปขวา ผ่านการส่งต่อเวกเตอร์ Hidden State (ht) และ Cell State (Ct)

แม้จะมี Forget Gate มาช่วยบรรเทาปัญหา Vanishing Gradient แต่จุดอ่อนเชิงโครงสร้างคือ:
1. ประมวลผลขนานไม่ได้ (Non-parallelizable): เพราะคำที่ t ต้องรอผลจากคำที่ t − 1 เสมอ
2. เกิด Context Decay: เมื่อประโยคยาวขึ้น ข้อมูลจากต้นประโยคจะค่อยๆ เลือนหายไปตามระยะทาง
3. มองเห็นบริบททิศทางเดียว (Unidirectional): ในช่วงที่อ่านต้นประโยค จะยังไม่รู้บริบทที่ซ่อนอยู่ท้ายประโยคครับ"
🖥️ สไลด์หน้า 4: Transformer & Scaled Dot-Product Attention
คลิกเปลี่ยนสไลด์ — ผายมือชี้สูตร Attention
"เพื่อแก้จุดคอขวดดังกล่าว Transformer จึงตัดโครงสร้างวนซ้ำทิ้งทั้งหมด และแทนที่ด้วยกลไก Scaled Dot-Product Self-Attention:"
Attention(Q, K, V) = softmax ( QKT √dk ) V
"สิ่งนี้ทำให้ระยะทางของข้อมูลหรือ Path Length ระหว่างทุกคำกลายเป็น O(1) โมเดลเชื่อมโยงคำคู่ใดๆ ได้โดยตรงในครั้งเดียว ไม่ว่าจะอยู่ห่างกันแค่ไหน และประมวลผลได้แบบสองทิศทาง (Bidirectional) ขนานบน GPU ได้อย่างเต็มประสิทธิภาพครับ"

"ผมขอยกตัวอย่างประโยคทดสอบคลาสสิก: 'The movie was not bad, but the ending was barely watchable.'
ประโยคนี้มีความซับซ้อนเพราะมีทั้งการปฏิเสธซ้อน (not bad) และคำเชื่อมขัดแย้ง (but) ตามด้วยข้อความเชิงลบ (barely watchable) ซึ่งภาพรวมเป็นรีวิว เชิงลบ (Negative) ครับ

ด้านซ้ายมือ — กลไก LSTM Tape Simulation:
*(เลื่อนเมาส์ชี้แถบไทม์ไลน์ของ LSTM)*
อาจารย์จะสังเกตเห็นว่า ขณะที่ LSTM ค่อยๆ อ่านทีละคำ ค่า Context Retention ของคำว่า 'not' และ 'bad' ในช่วงต้นประโยคจะค่อยๆ เสื่อมลง (Decay) เหลือเพียง 10-15% เมื่อไปถึงท้ายประโยค
*(เลื่อนเมาส์ชี้กล่อง Verdict ด้านล่างการ์ดซ้าย)*
ส่งผลให้เวกเตอร์ขั้นสุดท้าย hT แทบจำบริบทต้นประโยคไม่ได้ และถูกคำว่า 'watchable' ซึ่งเป็นคำเชิงบวกดึงดูด จนโมเดลทำนายผิดพลาดเป็น Positive (แถบเตือนสีแดง ความมั่นใจ 63.2%) ครับ

ด้านขวามือ — นวัตกรรมตารางเมทริกซ์ 2 มิติ (2D Attention Heatmap Grid):
*(ชี้ที่ตารางเมทริกซ์ 2D และคลิกปักหมุดที่ช่อง barely ➔ watchable)*
ในทางตรงกันข้าม ฝั่ง BERT เมื่อเราเปิดดู ตารางเมทริกซ์ 2 มิติ โดยแกนตั้งคือ Query (คำที่มอง) และแกนนอนคือ Key (คำที่ถูกมอง) และเลือกดู Head 2 ซึ่งเชี่ยวชาญด้าน Negation Binding:
เราจะเห็นจุดสีทองสว่างจ้าทันทีที่ช่องตัดกันระหว่างคำว่า 'barely' กับ 'watchable' สูงถึง 74% (หรือ 0.74 ในสเกลความน่าจะเป็น) และ 'not' กับ 'bad' สูงถึง 85% (0.85)
*(เลื่อนเมาส์ชี้กล่อง Verdict ด้านล่างการ์ดขวา)*
เมื่อคลิกปักหมุดที่ช่อง การ์ดด้านล่างจะแสดงการแทนค่าสูตร Softmax(QKT / √dk) ทุกคำเชื่อมโยงถึงกันโดยตรงด้วยระยะทาง Path Length = 1 ทำให้เวกเตอร์ [CLS] สรุปอารมณ์รีวิวนี้ที่ปลายทางได้อย่างถูกต้องเป็น Negative ด้วยความมั่นใจสูงถึง 96.4% (แถบสีเขียวทองยืนยันผล) ครับ"

*(ชี้ไปที่แถบการ์ดสรุป 3 เสาหลัก Error Archetypes ด้านบน)*
เมื่อเรามองดูแถบ Root Cause Analysis Summary ด้านบน ระบบได้จำแนกความล้มเหลวของ LSTM ทั้ง 183 เคสออกเป็น 3 กลุ่มหลักเชิงประจักษ์อย่างชัดเจนครับ:

2. ⚡ Contrastive Shift (58 เคส / 31.7%): การหักมุมด้วยคำเชื่อม เช่น 'however', 'although', 'but' ซึ่งน้ำหนักทัศนคติที่แท้จริงพลิกกลับหลังคำเชื่อม
3. ⏳ Long-Distance Context Decay (50 เคส / 27.3%): ประโยคยาวที่คำบอกทัศนคติอยู่ห่างกันเกินความสามารถของ LSTM ในการส่งผ่าน Hidden State ข้ามหลาย Time Steps

"ท่านอาจารย์ครับ ในฐานะวิศวกรคอมพิวเตอร์ เราไม่สามารถดูเพียงค่า Accuracy อย่างเดียวได้ แต่ต้องมอง Engineering Trade-off เสมอ
• LSTM ใช้เวลาเพียง 0.82 วินาทีต่อรอบ มีขนาดโมเดล 4 ล้านพารามิเตอร์
• BERT ใช้เวลาถึง 42.07 วินาทีต่อรอบ และมีขนาดถึง 110 ล้านพารามิเตอร์

BERT กินเวลาและทรัพยากรสูงกว่า LSTM ถึง 51.3 เท่า!
แต่สิ่งที่ได้รับกลับมาคือ ความแม่นยำที่พุ่งขึ้น Δ +30.40% (จาก 55.20% เป็น 85.60%) ซึ่งในโจทย์ธุรกิจจริง นี่คือความแตกต่างระหว่าง 'ระบบที่ใช้การไม่ได้' กับ 'ระบบที่พร้อมใช้งานในระดับโปรดักชัน' ครับ"
🖥️ สไลด์หน้า 12 & 13: บทสรุป ข้อเสนอแนะ และเปิดช่วง Q&A
คลิกสไลด์ 12 แล้วไป 13 — จบการนำเสนอด้วยความสุภาพและสง่างาม
"สรุปผลการวิจัยและข้อเสนอแนะเชิงประยุกต์ใช้งาน:
1. BERT ชนะขาดในทุกมิติ: หัวใจสำคัญคือ ความรู้จากการ Pre-training ร่วมกับกลไก Bidirectional Self-Attention
2. LSTM ยังไม่ไร้ค่า: หากเป็นงานบนอุปกรณ์พกพา, ระบบ IoT/Edge หรือระบบที่ต้องการการตอบสนองระดับมิลลิวินาที สถาปัตยกรรม Recurrent ยังเป็นตัวเลือกที่ประหยัดพลังงานที่สุด
3. ข้อจำกัด: ศึกษาบนชุดข้อมูลภาษาอังกฤษ 2,500 ตัวอย่าง ความยาว 128 โทเค็น ในอนาคตสามารถต่อยอดสู่ภาษาไทยและเอกสารขนาดยาวต่อไปครับ

กระผมขอจบการนำเสนอโครงงานไว้แต่เพียงเท่านี้ ขอขอบพระคุณท่านอาจารย์ ผศ. ดร.สมนึก สุระธง เป็นอย่างสูง และกระผมยินดีตอบทุกข้อซักถามครับ ขอบพระคุณครับ"

คลังแนวทางตอบคำถาม Defense (Anticipated Q&A Cheatsheet)

🎯 เตรียมพร้อมรับมือคำถามเจาะลึก
Q1: ทำไม LSTM ถึงได้ Accuracy ต่ำเพียง 55.20% (โมเดล Underfit หรือไม่?) ▼
แนวทางการตอบ:
สาเหตุหลักมาจาก 3 ปัจจัยร่วมกันครับ:
1. การฝึกจากศูนย์ (Trained from scratch): LSTM ไม่ได้ใช้ Pre-trained Word Embeddings (เช่น GloVe) แต่สุ่มน้ำหนักเวกเตอร์จากศูนย์บนข้อมูลเพียง 2,000 ตัวอย่าง ซึ่งน้อยเกินไปสำหรับการสร้าง Semantic Space ที่สมบูรณ์
2. ข้อจำกัดของรีวิว IMDb: รีวิวจริงมีความยาวเฉลี่ยกว่า 200 คำ แต่ถูก Truncate เหลือ 128 โทเค็น สาระสำคัญบางส่วนจึงตกหล่น
3. Context Decay: เกรเดียนต์และบริบทเสื่อมลงตามระยะทาง ทำให้ Loss ติดค้างที่ 0.3234 และแยกแยะคลาสได้ไม่เด็ดขาดครับ
Q2: เปรียบเทียบ BERT (Pre-trained) กับ LSTM (From Scratch) ถือว่ายุติธรรมไหม? ▼
แนวทางการตอบ:
ในเชิงวิทยาศาสตร์บริสุทธิ์ จุดตั้งต้นต่างกันครับ แต่ในเชิง 'วิศวกรรมการรู้จำรูปแบบประยุกต์' นี่คือการพิสูจน์เปรียบเทียบระหว่าง 'กระบวนทัศน์ดั้งเดิม (Train from scratch)' กับ 'กระบวนทัศน์สมัยใหม่ (Pre-train once, Fine-tune anywhere)' เพื่อตอบคำถามว่าคุ้มค่าหรือไม่ที่จะจ่ายต้นทุนเวลาเพิ่ม 51.3 เท่า ซึ่งผลการทดลองพิสูจน์แล้วว่าคุ้มค่ามาก เพราะได้ความแม่นยำเพิ่มขึ้นถึง Δ +30.40% ครับ
Q3: ทำไมถึงเลือกตัดความยาวประโยคที่ 128 โทเค็น ไม่ใช้ 512 ตามขีดจำกัดของ BERT? ▼
แนวทางการตอบ:
1. การควบคุมตัวแปรเพื่อความเท่าเทียม (Controllability): หากขยายเป็น 512 โทเค็น LSTM จะเกิด Vanishing Gradient และ Context Decay รุนแรงยิ่งขึ้นจนประสิทธิภาพลดลงไปอีก
2. Computational Budget: กลไก Self-Attention มีความซับซ้อนเชิงหน่วยความจำและเวลาอยู่ที่ O(N2) ค่า 128 จึงเป็นจุดสมดุลที่ดีที่สุดบน GPU NVIDIA T4 ในการรัน Batch Size 16-32 ได้อย่างมีเสถียรภาพครับ
Q4: เวลาต่างกัน 51.3 เท่าในตอน Train แล้วตอนทำนายจริง (Inference) ต่างกันเท่าไร? ▼
แนวทางการตอบ:
ตอน Inference ความเร็วจะต่างกันลดลงเหลือประมาณ 10–20 เท่าครับ เพราะไม่ต้องคำนวณ Backward Pass และในโปรดักชันจริงเราสามารถประยุกต์ใช้เทคนิค Quantization (INT8), Pruning หรือ Knowledge Distillation (เช่น DistilBERT) เพื่อบีบอัดโมเดลให้เร็วและเบาขึ้นได้อีกมากครับ
